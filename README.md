# 音声編集アプリ

波形を見ながら不要な部分をカットし、音量を調整して書き出すための、Windows 向けデスクトップ音声編集アプリケーションです。
（要件の詳細は [REQUIREMENTS.md](./REQUIREMENTS.md) を参照してください。）

## 開発状況

段階的に開発を進めています。

- **ステップ1**: Electron + Vite でプロジェクトの土台を構築。アプリのウィンドウが起動し、「ファイルを開く」ボタンから MP3 / WAV / M4A ファイルを選択するダイアログを表示できるところまで。
- **ステップ2**: 波形表示（要件4.1）を実装。
  - wavesurfer.js による波形表示（MP3 / WAV / M4A 対応）
  - 再生・一時停止・停止 / 波形クリックによるシーク / プレイヘッド表示
- **ステップ4（現在）**: 範囲選択とカット（要件4.2）を実装。
  - 波形上のドラッグで編集範囲を選択（**複数箇所**対応）
  - 各範囲は端をドラッグして始点・終点を微調整可能
  - 範囲をクリックして選択 →「選択範囲を削除」ボタン（または Delete キー）で削除
  - 選択した範囲（複数可）を**まとめてカット**。カット後は前後が結合され、波形・プレイヘッドが更新後の状態に再描画されます。
  - カットは ffmpeg でディスク上のファイルを処理し、結果は一時ファイルとして扱います（**元ファイルは変更しません**）。
  - 音量調整・書き出し・アンドゥ/リドゥはまだ実装していません。

### 長尺（最長3時間）音声への対応方針

要件5.1のとおり、最長3時間の音声を扱ってもメモリが破綻しない設計にしています。

- **波形はピークデータで描画**: 音声ファイル全体をメモリに展開せず、メインプロセスで ffmpeg により 8kHz モノラルへダウンサンプリングしながら PCM をストリーム処理し、**固定本数（8000点）のピーク配列**へ集約します。ファイルの長さに関わらずピーク配列のサイズは一定で、処理中に保持するのは小さなチャンクとピーク配列のみです。
- **再生はストリーミング**: 波形描画時はファイル全体のデコードを行いません。再生はカスタムプロトコル（`app-audio://`）＋ HTTP Range で必要な範囲だけを配信するため、`<audio>` 要素がファイル全体を読み込むことなくストリーム再生・シークできます。
- **カットもディスク上で処理**: カットは AudioBuffer をメモリに全展開して結合するのではなく、ffmpeg の `atrim` + `concat` フィルタで「残す範囲」だけをディスク上のファイルからストリーム処理し、新しい一時ファイル（可逆の FLAC）として書き出します。メモリ使用量はファイルの長さに依存しません。複数範囲の同時カットも 1 回の ffmpeg 実行で行います。

### 編集操作の状態管理（アンドゥ/リドゥに向けた設計）

編集操作をあとから取り消せるよう、メインプロセスの `EditSession` がドキュメントの「版履歴」を管理します。各カット操作の結果を version（音声ファイル・長さ・ピーク・操作内容）として積んでいく構造で、将来のアンドゥ/リドゥは履歴のインデックスを前後させるだけで実装できます。元ファイルは常に保持し、編集結果は一時ファイルとして別に保存します（アプリ終了時に一時ファイルを削除）。

### M4A の読み込みについて

- **波形（ピーク）生成**: ブラウザ標準（Web Audio API の `decodeAudioData`）は M4A をデコードできますが、ファイル全体をメモリ上の AudioBuffer に展開するため長尺では破綻します。そこで **ffmpeg（`ffmpeg-static`）でストリームデコードしてピークを生成**します。
- **再生**: Electron に同梱される Chromium は AAC/M4A を標準再生できるため、`<audio>` 要素でそのまま再生します。

### 非 PCM / 非標準フォーマットの読み込み（正規化）

拡張子が `.wav` でも、中身が ADPCM（`adpcm_ima_wav` など）や μ-law といった圧縮形式の場合、Chromium はデコードできず再生できません（波形はメインプロセスの ffmpeg で作るため、表示だけは成功してしまいます）。

そこで**読み込み時に ffprobe でコーデックを調べ、ブラウザが素で再生できない形式だけ ffmpeg で 16bit PCM WAV（`pcm_s16le`）の一時ファイルへ変換**してから扱います（`src/main/normalize.js`）。

- **サンプルレート・チャンネル数は元の値を維持**し、コーデックのみ正規化します。ただし Web Audio が扱えない極端なサンプルレート（3000Hz 未満 / 384000Hz 超）の場合のみ 48kHz へ載せ替えます。
- **変換するのは必要なときだけ**です。`pcm_s16le` / MP3 / AAC / FLAC / Vorbis / Opus は Chromium がそのまま再生できるため変換しません（3時間の MP3 を WAV へ展開すると数 GB の一時ファイルになり、再生上の利点も無いためです）。
- 変換後は**再生・波形・カット・音量調整・書き出しのすべてが正規化済みファイルを入力**にします。**元ファイルは変更しません**。
- 一時ファイルはセッションの一時ディレクトリに置かれ、別ファイルを開いたとき・アプリ終了時にカットの中間ファイルとまとめて削除されます。

### WMA（Windows Media Audio）の読み込み

WMA を**入力として**扱えます。「ファイルを開く」「末尾にファイルを追加」「一括結合」のいずれでも選択できます。

- Chromium は WMA を再生できないため、読み込み時に**上記の正規化と同じ経路**で 16bit PCM WAV（`pcm_s16le`）へ変換します。`normalize.js` の `PLAYABLE_CODECS` は「そのまま再生できるコーデックを挙げる許可リスト」なので、`wmav1` / `wmav2` / `wmapro` / `wmalossless` / `wmavoice` はいずれもここに含まれず、つねに変換対象になります。サンプルレート・チャンネル数は元の値を維持します。
- **WMA は出力形式には入れていません。** レガシー形式で新規に書き出す用途がないためです（`format.js` の出力定義は変更していません）。WMA を開いた状態での保存は、**MP3 / WAV / M4A / MP4 から選ぶ形式変換保存**になります。編集をしていなくても、入力（ASF / WMA）と出力は必ず別形式になるため、そのまま書き出せます。
- 保存ダイアログのデフォルトのファイル名は `元ファイル名-converted.mp3` になります。WMA の拡張子はそのままでは出力できないため、**出力できる形式（MP3）へ寄せて**います。
- 一括結合では、WMA と他の形式を**混在させても構いません**。全ファイルを並び順の先頭ファイルのサンプルレート・チャンネル数へ揃えてから連結する仕組みなので、先頭が WMA でもそれ以外でも同じように動きます。

> **入力形式の定義箇所**: 対応する入力形式は `format.js` の `INPUT_EXTENSIONS` 1か所で定義し、3つのファイル選択ダイアログ（開く／末尾に追加／一括結合）と、末尾追加・一括結合の受け入れ判定、エラーメッセージの文言がすべてそこを参照します。形式を増やすときはこの1か所だけを直せば揃います。

### 末尾へのファイル追加（結合）

ツールバーの「末尾にファイルを追加」から、別の音声ファイル（MP3 / WAV / M4A / WMA）を編集中の音声の末尾に連結できます。連結した時点で**1本の音声に統合**され、以降はカット・音量調整・書き出しの対象として通常どおり扱えます（複数トラックやプレイリストのような概念は持ちません）。**元ファイル・追加したファイルはどちらも変更しません**。

- 連結結果は**カット・音量調整と同じ「版」として履歴に積まれる**ため、アンドゥ/リドゥでそのまま前後に移動できます。連結後は波形を全長ぶん作り直して表示を更新します。
- 連結は ffmpeg の **concat demuxer**（`-f concat -safe 0 -c copy`）で行います。再エンコードしないためディスク I/O だけで完結し、長尺でもメモリに全展開しません。
- concat demuxer は**入力どうしのサンプルレート・チャンネル数の食い違いを検出せず**、そのまま繋いだ壊れた（再生速度やチャンネル配置がおかしい）出力を作ってしまいます。そこで連結前に、追加ファイルを「元から同じパラメータに見えても必ず」現在の編集対象と同じサンプルレート・チャンネル数の 16bit PCM WAV へ変換します。現在の編集対象も、同じパラメータの PCM WAV でなければ同様に変換します（カット/音量調整の中間ファイルは FLAC、元ファイルは MP3 / M4A のことがあるため）。
- 連結用のリストファイルは一時ディレクトリに作り、各行を `file '<絶対パス>'` 形式で書き出します。パスはシングルクォートで囲み、パス中のシングルクォートはエスケープするため、**日本語・スペース・記号を含むパスでも動作します**（Windows の `C:\...` もクォート内ではそのまま扱われます）。
- 変換で作った中間ファイルとリストファイルは、**処理が終わった時点で（失敗時も含めて）削除**します。対応外の形式が選ばれた場合や ffprobe / ffmpeg が失敗した場合は、版を積まずに直前の状態を保ったままエラー内容を表示します。
- **連結後の長さが上限（要件5.1 の3時間）を超える場合は、変換を始める前に警告して中断**します（版は積まれず、一時ファイルも作られません）。判定は現在の長さと追加ファイルの長さ（ffprobe）の合計で行うため、長い処理を始めてから中断することはありません。

### 編集なしでのフォーマット変換保存

保存ボタンは**ファイルを開いていればつねに有効**です。編集（カット・音量調整・末尾への追加）をしていなくても、保存ダイアログで入力と違う形式を選べば**形式変換として書き出せます**（例: WAV を開いて、編集せずに MP3 で保存）。

- 書き出すかどうかは、**保存ダイアログで出力形式が決まってから**判断します。
  - 編集が1つ以上ある → 従来どおり書き出す
  - 編集がなく、出力形式が入力ファイルと**同じ** →「変更がありません」と表示して中断する（ファイルは作りません）
  - 編集がなく、出力形式が入力ファイルと**違う** → 形式変換として ffmpeg で書き出す
- **同じ形式かどうかは拡張子ではなく、ffprobe が返すコンテナ（`format_name`）とコーデック（`codec_name`）で判定**します（`src/main/format.js`）。そのため、ADPCM の `.wav` を `.wav`（`pcm_s16le`）として保存する場合や、24bit PCM を 16bit PCM で保存する場合は「変換あり」として書き出します。読み込み時に正規化した音声（ADPCM・極端なサンプルレート）も、その時点で中身が変わっているため常に変換扱いです。
- 出力形式の定義（ffmpeg へ渡すコーデック引数と、書き出した結果のコンテナ／コーデック）は `format.js` の1か所にまとめ、書き出しと判定がずれないようにしています。
- **形式変換だけの保存でも版履歴（アンドゥ/リドゥ）は変化しません。** 元ファイルも変更しません。
- デフォルトのファイル名は、編集がある場合は `元ファイル名-edited.<元の拡張子>`、編集がない場合は `元ファイル名-converted.<元の拡張子>` です（要件4.5 のとおり、元ファイルを上書きしないよう、どちらの場合も接尾辞を付けます）。

### 複数ファイルの一括結合

ツールバーの「複数ファイルを結合」から、選んだ複数の音声ファイル（MP3 / WAV / M4A / WMA）を一覧の順番どおりに繋いで**1本のファイルとして保存**できます。**ファイルを開いていなくても使えます**。

「末尾にファイルを追加」が編集中の音声に1ファイルずつ足していく機能なのに対し、こちらは10ファイル以上をまとめて処理して書き出すための独立した機能です。**現在の編集セッション（版履歴・アンドゥ/リドゥ）には一切影響しません**し、素材にしたファイルも変更しません。

- **並び順は自然順ソート**で初期表示します。ファイル名の数字部分を数値として比べるため、`1.wav` → `2.wav` → `10.wav` の順になります（単純な文字列ソートだと `1` → `10` → `2` になってしまいます）。ゼロ埋め（`track-002`）や大文字小文字の違いがあっても安定して並びます。
- 確認ダイアログで**各ファイルの名前と長さ（秒）・合計時間**を確認し、「↑」「↓」で並べ替え、「除外」で一覧から外せます。結合位置の指定はなく、**常に一覧の順番どおり**に繋ぎます。
- 「結合して保存」で保存ダイアログを開き、**出力先と形式（MP3 / WAV / M4A / MP4）**を選んで書き出します。デフォルトのファイル名は `先頭ファイル名-concat.<先頭ファイルの拡張子>` です。
- 保存が終わると「結合したファイルを開きますか？」と確認します。「はい」なら結合結果を編集対象として読み込みます（**現在編集中の内容は破棄される**旨もダイアログに出ます）。MP4 は書き出し専用の形式なので、この確認は出ません。

#### 結合のしくみ

連結処理は「末尾へのファイル追加」と同じ `src/main/concat.js` を使います。

1. 全ファイルを、**並び順の先頭ファイル**のサンプルレート・チャンネル数に揃えた 16bit PCM WAV（`pcm_s16le`）へ変換する
2. concat demuxer（`-f concat -safe 0 -c copy`）で連結する
3. 連結結果を、選ばれた出力形式（`src/main/format.js` の定義）へ変換して書き出す

パラメータを揃えてから繋ぐのは、concat demuxer が**入力どうしのサンプルレート・チャンネル数の食い違いを検出せず**、そのまま繋いだ壊れた（再生速度やチャンネル配置がおかしい）出力を作ってしまうためです。

出力形式が WAV（16bit PCM）の場合は、**連結結果をそのまま出力先へ書き出します**（3時間ぶんで数 GB になるファイルを二度書きしないための最適化です）。

#### エラー処理・進捗

- **2ファイル未満**しか選ばれていない場合は、その旨を表示して結合しません。
- **合計が上限の3時間（要件5.1）を超える場合**は、確認ダイアログの時点で警告を出し、「結合して保存」を無効化します。時間のかかる変換を始める前に止まります。
- **読めない・壊れたファイル**があった場合は、`「5.wav」の読み込みに失敗しました: ...` のように**どのファイルで失敗したかが分かるメッセージ**を出して中断します。判定は確認ダイアログを出す前（ffprobe でのメタデータ読み取り）と、実際の変換時の両方で行います。
- 処理中は「変換中… (3/12) 03.wav」のように**何ファイル目を処理しているか**を表示します。
- 中間ファイルは結合専用の一時ディレクトリにまとめ、**成功時・失敗時とも削除**します。失敗した場合は書きかけの出力ファイルも消します。
- 出力先に**素材のファイル自身**が指定された場合は、上書きしてしまう前に弾きます。

> **一時ディレクトリの空き容量について**: いったん全ファイルを非圧縮の PCM WAV へ揃えるため、一時ディレクトリには**合計時間ぶんの非圧縮データ**が必要です（48kHz ステレオなら1時間あたり約 690MB、上限の3時間で約 2GB）。MP3 / M4A / MP4 で書き出す場合は連結結果の WAV も作るため、ピークで**その約2倍**を使います。メモリ使用量は長さに依存しません（ディスク上でストリーム処理するため）。

### MP4（動画）での書き出し

出力形式に **MP4** を選ぶと、**1280x720 の黒一色の静止画を全編に敷いた動画**として書き出します。通常の保存（編集後の書き出し・形式変換だけの保存）でも、一括結合の保存でも選べます。

YouTube は音声のみのファイルを受け付けないため、音声を投稿するには映像トラックを持つ動画にする必要があります。その用途に合わせた設定です。

| 項目 | 設定 |
| --- | --- |
| 映像 | H.264（libx264）/ 1280x720 / `yuv420p` / High プロファイル |
| フレームレート | 5fps（静止画のため。キーフレーム間隔は約2秒） |
| 音声 | AAC 192kbps |
| その他 | `-movflags +faststart`（moov atom を先頭に配置） |

#### 処理時間（実測）

3時間（10800秒）のステレオ音声を書き出したときの実測値です（4コアの環境）。

| 出力 | 所要時間 | ファイルサイズ |
| --- | --- | --- |
| 音声のみ（AAC 192k） | 247 秒 | 248 MB |
| **MP4（5fps）** | **294 秒** | **253 MB** |
| MP4（15fps） | 419 秒 | 272 MB |

書き出し時間はほとんど**音声（AAC）のエンコード**で決まります。映像は黒一色なので圧縮がほぼ効き、5fps ならその下限（247秒）に対して +47 秒で収まります。フレームレートを上げると映像側が律速に変わるため、静止画に必要のない 15fps では +2分ほど余計にかかります。逆に 1fps まで落としても下限より速くはならないので、極端に低い値は避けて 5fps にしています。

- **MP4 は書き出し専用**です。映像を含むため、「ファイルを開く」「末尾にファイルを追加」「一括結合」の入力としては受け付けません（入力は MP3 / WAV / M4A / WMA のみ）。
- M4A の `format_name` は `mov,mp4,m4a,3gp,3g2,mj2` で **mp4 を含む**ため、コンテナ名だけで比べると「M4A を MP4 で保存」が「変換の必要なし」と誤判定されます。MP4 は映像トラックを足す形式なので、**同一判定からは常に除外**しています（M4A を開いて MP4 で保存すると、きちんと動画として書き出されます）。
- 映像は `-f lavfi -i color=c=black:...` の仮想入力で生成します。この入力は止めない限り無限にフレームを作り続けるため、**音声の長さを `-t` で与えて終端**しています。`-shortest` だけに任せると多重化バッファのぶん映像が先に進み、実測で**音声より約2秒長い**出力になりました。`-fflags +shortest` を足すと今度は**音声の末尾が数百ミリ秒切り落とされる**ため、長さを明示する方法を採っています。

## Windows PC でのセットアップ手順

### 1. 前提ソフトウェアのインストール

以下を事前にインストールしておいてください。

- **[Node.js](https://nodejs.org/)**（LTS 版、v20 以上を推奨）
  - インストーラーに同梱される **npm** も一緒に入ります。
- **[Git](https://git-scm.com/download/win)**（リポジトリを取得する場合）

### Linux 上でクロスビルドする場合の注意

CI やコンテナなど Linux から Windows 版を作る場合、そのままでは**動かないインストーラー**が
出来上がります。以下の2点が必要です。

**1. Windows 用の ffmpeg バイナリを取り直す（必須）**

`ffmpeg-static` は `npm install` を実行した OS 向けのバイナリだけをダウンロードします。
Linux でインストールしたまま Windows 版をビルドすると、**Linux の ELF バイナリが同梱され、
Windows 上では波形生成・カット・保存・結合のすべてが失敗します**（インストール自体は成功し、
起動もするため気づきにくい）。

```bash
cd node_modules/ffmpeg-static
npm_config_platform=win32 npm_config_arch=x64 node install.js   # ffmpeg.exe を取得
cd ../..
```

`file node_modules/ffmpeg-static/ffmpeg.exe` が `PE32+ executable ... x86-64` になっていれば
正しい状態です。ローカルでアプリを動かすときは、Linux 用のバイナリ（拡張子なしの `ffmpeg`）が
同じディレクトリに残っているのでそのまま使えます。

**2. wine（32bit）を用意する**

electron-builder は実行ファイルのバージョン情報を書き込む `rcedit` と、NSIS の
アンインストーラー生成のために Windows の実行ファイルを動かします。どちらも **32bit の
PE バイナリ**なので、`wine64` だけでは足りません（`wine: could not exec the wine loader` や
`failed to load ntdll.dll` で失敗します）。

```bash
dpkg --add-architecture i386
apt-get update
apt-get install -y --no-install-recommends libgd3:i386 wine32

# wine32 パッケージは /usr/bin にランチャーを置かない。wine は argv[0] の位置から
# ライブラリを探すため、シンボリックリンクではなく exec するラッパーを作る
printf '#!/bin/sh\nexec /usr/lib/wine/wine "$@"\n' > /usr/bin/wine && chmod +x /usr/bin/wine

# 32bit 専用のプレフィックスを用意する
export WINEARCH=win32 WINEPREFIX=~/.wine32 WINEDEBUG=-all
wine wineboot --init
```

> `libgd3:i386` を先に入れているのは、`wine32` が依存する `libgphoto2` の i386 版が
> これを要求し、素直に `apt-get install wine32` すると依存解決に失敗するためです。

### 同梱サイズについて

`ffprobe-static` は npm パッケージに全プラットフォーム分のバイナリを含んでいます。
`electron-builder.yml` の `files` で macOS / Linux 用を除外しているため、Windows 版には
`bin/win32` だけが入ります。除外前は `win-unpacked` が 672MB でしたが、除外後は 443MB です。

さらに絞るなら `bin/win32/ia32` も除外できます（x64 のみをターゲットにしているため実行時には
使われません。約 50MB）。将来 32bit 版を作る可能性を残して、いまは同梱したままにしています。

## プロジェクト構成

```
audio-editor/
├── electron.vite.config.js   # electron-vite の設定
├── electron-builder.yml      # Windows インストーラーの設定
├── src/
│   ├── main/                 # メインプロセス
│   │   ├── index.js          #   ウィンドウ生成・ファイルダイアログ・音声ストリーム配信・IPC
│   │   ├── binaries.js       #   ffmpeg / ffprobe のパス解決（asar unpacked 対応）
│   │   ├── peaks.js          #   ffmpeg による波形ピーク生成（メモリ安全なストリーム処理）
│   │   ├── normalize.js      #   読み込み時のコーデック正規化（ADPCM 等 → 16bit PCM WAV）
│   │   ├── concat.js         #   ファイル連結用の変換・concat demuxer 処理
│   │   ├── batchConcat.js    #   複数ファイルの一括結合（自然順ソート・結合・書き出し）
│   │   ├── duration.js       #   長さの上限（3時間）と表示用の整形
│   │   ├── format.js         #   入力形式と出力形式の定義・同一判定・書き出し
│   │   └── editSession.js    #   版履歴の管理と ffmpeg によるカット・書き出し処理
│   ├── preload/              # プリロード（レンダラーへ安全に API を公開）
│   │   └── index.js
│   └── renderer/             # 画面（UI）
│       ├── index.html
│       ├── main.js           #   波形表示・再生コントロール・一括結合のダイアログ
│       └── style.css
├── REQUIREMENTS.md           # 要件定義書
└── README.md
```
